# 论文写作协作历史

本目录专门保存作者与 AI 围绕论文写作产生的持续记录。它承担论文叙事的版本记忆：论文故事可以随着实验结果和理论分析调整，但每次重要变化都应可追溯。

## 记录范围

应记录：

- 论文问题定义、核心矛盾与整体故事；
- 贡献点的主次关系和措辞变化；
- 理论命题、假设、证明路线及其适用边界；
- Introduction、Related Work、Method、Experiments 等章节的组织决策；
- 审稿风险、claim 边界和因新实验而发生的叙事调整；
- 对作者语言、叙述和公式风格的观察。

代码变动、调试过程、实验运行和原始结果应优先记录在 `chat-history/`。论文记录引用实验结论时，应链接对应工程历史及机器生成结果，而不是复制后失去来源。

## 核心文件

- `YYYY-MM-DD-NN-current-narrative.md`：该时点有效的论文故事与贡献定义；
- `YYYY-MM-DD-NN-claim-evidence-ledger.md`：该时点的论文主张到实验、理论和实现证据映射；
- `YYYY-MM-DD-NN-topic.md`：每次论文讨论或叙事变化的历史快照。

除 `README.md` 外，本目录中的所有文件都必须遵循相同的日期—序号命名规范。叙事或证据台账发生实质变化时，应创建新的带日期版本，不覆盖旧版本；文件名中日期和序号较新的版本视为当前版本。

## 命名规范

新历史文件统一命名为：

```text
YYYY-MM-DD-NN-topic.md
```

创建前检查当天已有记录，并使用下一个两位序号。

## 叙事变更规则

每次实质性变更应说明：

1. 原叙事或原 claim；
2. 触发变化的新实验、理论发现或审稿风险；
3. 新叙事及其证据边界；
4. 受影响的论文段落、图表和待补实验；
5. 对最新 narrative 与 claim-evidence ledger 版本的同步更新。

论文中的“最好”“SOTA”“保持”“理论保证”等强表述，只有在 ledger 中证据状态达到可用标准后才能写入正式稿件。
