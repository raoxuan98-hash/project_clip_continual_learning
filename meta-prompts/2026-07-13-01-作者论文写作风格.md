# 作者论文写作风格

**日期**: 2026-07-13  
**用途**: 作为本项目论文写作的全局风格约束。分析依据包括作者自定义的 `xuan-research-paper-writing` skills，以及作者提交至 TPAMI 的论文 `my_paper_submitted_to_tpami.pdf`。实际论文样本的权重高于通用模板。

---

## 1. 总体风格

作者偏好问题驱动、机制密集、证据约束的技术写作。叙述通常不是从方法名称或模块列表开始，而是先把整体困难拆解为若干相互关联但职责明确的技术瓶颈，再分别推出对应设计。

典型论证链为：

> 任务背景 → 具体瓶颈 → 现有方案为何不足 → 经验或理论观察 → 方法设计 → 数学形式 → 算法含义 → 实验证据。

不偏好空泛的宏大背景、过多应用场景铺垫或仅靠形容词建立创新性。

## 2. 段落组织

- 一段集中表达一个技术信息，但允许在段末承担向下一段过渡的功能。
- 段首通常直接提出判断、困难或目标，例如 `A critical challenge is...`、`To resolve this issue...`、`Building upon...`。
- 段落内部常采用因果推进：事实 → 后果 → 方法需求。
- 模块介绍遵循 `motivation → mechanism → consequence/advantage`，但不机械使用粗体 `Motivation`、`Design`、`Advantage` 标签。
- 偏好显式过渡词，如 `However`、`Consequently`、`Specifically`、`To this end`、`In contrast`、`Notably`，以保证长技术链条可跟踪。
- 小节内部可使用 `a)`, `b)`, `c)` 形式的细粒度标题，将推导、复杂度和实现步骤分开。

## 3. 引言风格

- 尽早提出具体技术瓶颈，而不是长篇介绍领域重要性。
- 喜欢将困难拆为两个或多个相互耦合的问题，并说明单独解决其中一个为什么仍不充分。
- 方法不是一次性整体抛出，而是按问题顺序逐个引出。
- 经验观察、复杂度事实或概念图可在引言早期出现，用于证明瓶颈真实存在。
- 贡献列表包含具体机制、复杂度或理论结论，而不是只写模块名称。
- 当前 CLIP 项目需比 TPAMI 样本更克制：LoRA-NF 是唯一主线，蒸馏和集成分类器只补足相应职责。

## 4. Related Work 风格

- 按技术机制或问题类别组织，不按年份或论文逐篇罗列。
- 每一类先概括共同策略，再列代表方法，最后指出该类方法与本文问题的局部差距。
- 对接近工作给出精确机制差异，避免笼统写成 `existing methods fail to...`。
- 本文定位通常放在相关工作段落结尾，用一至两句完成，不重复贡献列表。
- 允许对方法进行分类枚举，但每个类别必须服务于后续方法动机。

## 5. 方法与公式风格

- 公式出现前先说明目标或瓶颈；公式之后立即使用 `where` 定义符号。
- 推导顺序偏好从经典形式出发，再逐步重参数化或分解到提出的方法。
- 重要公式单独编号；多步等价或推导使用对齐结构。
- 正式结论采用 `Lemma`、`Proposition` 和 `Remark` 分层：
  - Lemma/Proposition 给出条件和结论；
  - 主文给出简短证明思路或关键步骤；
  - Appendix 给出完整证明；
  - Remark 将数学结果翻译成复杂度、优化或实践含义。
- 理论条件必须显式陈述，不能把假设下结论写成普遍保证。
- 符号在首次使用附近定义，不依赖读者反复查 notation table。
- 算法描述不照搬代码，而是转译为输入、状态、更新与输出。

## 6. 实验写作风格

- 实验围绕研究问题组织，而非简单按表格顺序叙述。
- 结果段落通常先给总体趋势，再给关键数字，最后解释机制含义。
- 偏好设计能够隔离组件贡献的成对或阶梯式对照。
- 超参数实验不仅报告最优点，还强调稳定区间、敏感性和默认值为何合理。
- 会主动讨论方法失效或稍弱的设置，并提出与表示分布或假设相关的解释。
- 理论中的可验证预测应在实验中有直接对应，例如谱能量、历史响应、复杂度或误差界相关因素。

## 7. 语言习惯

- 语气正式、直接、偏技术性；常用主动语态 `we propose`, `we model`, `we derive`, `we show`。
- 倾向使用长复合句表达完整因果链，但每句仍应只有一个主要逻辑中心。
- 喜欢使用 `tightly coupled`, `fundamentally constrained`, `building upon`, `this structure allows`, `this observation indicates` 等逻辑性表达。
- 不应为了模仿风格而重复使用 `novel`, `remarkably`, `provably`, `state-of-the-art`；强词必须由当前项目证据支持。
- 不使用过多修辞、设问或口语化表达。

## 8. 当前项目的适配规则

当前论文没有预设投稿 venue，也没有固定篇幅限制。`paper-template` 中使用的 NeurIPS 样式只是当前 LaTeX 载体，不能据此推导投稿目标或页数约束。写作应优先保证论证完整、推导清晰和实验充分，而不是为了压缩页数牺牲必要内容。

- 引言保留机制直觉，正式理论进入方法正文；这一安排服务于叙事层级，而不是篇幅限制；
- 方法正文可以完整给出关键命题、证明思路和解释性 Remark；较长的代数推导仍可放入附录，以维持主线可读性；
- Related Work 可以充分建立传统 CIL、VLM 持续学习和零空间适配的技术谱系，只需避免无关文献罗列；
- 实验可以包含完整的主实验、机制验证、消融、稳健性与复杂度分析；
- LR-RGDA 和蒸馏的篇幅由其技术复杂度与论文职责决定，但叙事层级仍低于 LoRA-NF；
- 不因篇幅主动删除有助于证明创新边界、理论条件或实验可信度的内容；
- 仍应避免跨章节机械重复，因为这是信息组织问题，而不是长度问题。

## 9. 写作检查表

- [ ] 每段是否有唯一的中心信息？
- [ ] 方法是否由具体瓶颈自然推出？
- [ ] 公式前是否说明目的，公式后是否定义符号并解释意义？
- [ ] 正式结论是否包含必要条件？
- [ ] 模块篇幅是否与贡献和证据强度一致？
- [ ] 实验是否回答明确问题并隔离组件贡献？
- [ ] 是否删除了重复的形容词、贡献宣称和跨章节复述？
- [ ] 是否在没有人为篇幅压缩的前提下，完整保留作者的因果推进、理论解释和实验证据？
