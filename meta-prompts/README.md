# 项目全局认知与元提示

`meta-prompts/` 保存位于逐次对话历史之上的项目级全局认知，供后续 AI 在进入项目时快速建立稳定、整体的理解。

## 与历史目录的区别

- `meta-prompts/`：保存跨会话长期有效的全局认知、项目定位、核心概念、目录语义和 AI 工作方式；
- `chat-history/`：保存代码、实验、调试、结果和工程决策的时间序列记录；
- `chat-history-for-paper-writing/`：保存论文故事、理论路线、贡献表述和写作决策的时间序列记录。

简言之，history 回答“项目如何一步步演化”，meta-prompts 回答“理解整个项目时应采用什么认知框架”。

## 适合保存的内容

- 项目的总体目标、阶段和核心研究矛盾；
- 各目录、子系统和主要文件在整体项目中的角色；
- 算法模块之间的关系及稳定的高层解释；
- 阅读项目、分析实验或协助论文时应遵循的认知顺序；
- 用户希望 AI 长期保持的术语、边界、偏好和判断原则；
- 对多份历史记录进行提炼后形成的全局总结。

## 不适合保存的内容

- 单次调试过程、临时实验状态或未经核验的数字；
- 仅对某次对话有效的待办事项；
- 每次论文措辞调整的完整过程；
- 可直接从代码或配置读取、且频繁变化的细节清单。

这些内容应分别进入相应 history 目录。需要时，meta-prompt 可以链接历史记录或事实台账，但不应复制并固化容易过时的数据。

## 维护规则

- 内容应经过提炼，强调稳定认知而非流水账；
- 当项目目标、核心算法或论文主线发生实质变化时，应更新或新增相应 meta-prompt；
- 带日期的文件表示某一时点形成的认知版本，不应静默覆盖重要旧版本；
- 若内容与最新代码或经核验实验冲突，以代码、配置、原始结果及最新历史记录为准，并随后修订全局认知；
- AI 开始较大规模的项目分析、代码整理或论文工作前，应优先阅读本 README 和相关 meta-prompt。
