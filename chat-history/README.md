# 项目协作历史

本目录保存与项目工程实现和实验事实有关的 AI 协作记录，是代码演进、实验复现和技术决策的长期记忆。

## 记录范围

应记录：

- 代码、配置、脚本和项目结构的变动；
- 实验设计、运行状态、结果汇总和异常诊断；
- 算法实现决策、超参数选择和复现条件；
- 与项目工程或实验有关的待办事项；
- 能够支持论文结论的原始事实及其文件位置。

论文故事、贡献措辞、章节结构和叙事版本变化应记录在 `chat-history-for-paper-writing/`，避免将实验事实与论文解释混为一体。一次协作同时涉及两者时，可以在两个目录分别记录，并相互链接。

## 命名规范

新文件统一命名为：

```text
YYYY-MM-DD-NN-topic.md
```

- `NN` 是当天递增的两位序号；
- `topic` 使用简短、稳定的英文短语；
- 创建前先检查当天已有文件，使用下一个可用序号；
- 历史文件即使存在重复序号或旧格式，也不要仅为统一命名而批量重命名，以免破坏已有引用。

## 推荐内容

每条记录至少包含日期、会话概况、关键决策、重要发现、待办事项和相关文件。实验记录还应尽可能包含：

- 配置文件和启动命令；
- 数据集、任务顺序和随机种子；
- 代码提交或其他可识别版本；
- 日志与结果文件的路径；
- 指标定义及聚合方式；
- 结果是否为试运行、单种子或正式多种子结果。

## 事实使用规则

- 历史记录是索引，不自动等同于最终论文证据；
- 论文采用数字前，应回溯到机器生成的结果文件、配置和日志；
- 出现乱码、缺失版本号或指标口径不明时，应标记为待核验；
- 已被后续实验推翻的结论应保留，但必须链接到取代它的新记录。
